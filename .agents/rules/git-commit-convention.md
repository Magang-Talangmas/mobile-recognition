# Git Commit Convention Rule

Always use strict Conventional Commits format for git commit messages:

- `feat: <short description>` -> For new features or user-facing additions
- `fix: <short description>` -> For bug fixes or logic repairs
- `style: <short description>` -> For UI layout, spacing, icons, or design tweaks
- `refactor: <short description>` -> For code cleaning or structural improvements without feature changes
- `chore: <short description>` -> For build config, dependencies, or gitignore updates
- `docs: <short description>` -> For documentation changes

Rules:
- Never use generic commit messages like "Update UI", "fix_ui_and_features", "change code".
- Keep messages lowercase, clear, and descriptive in standard Conventional Commit syntax.
